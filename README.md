- Make it observable. If I can't see CPU, memory, and disk in real time, I don't understand the system.

- Finish the last 10%. Sanitization, error states, and empty states are the product.

### 🌩️ Cloud Burst Detection System

> **Problem.** Cloudbursts in the Indian Himalayas kill people every monsoon, and warning data is scattered across satellite feeds that no one outside a meteorology lab can read.

**What it does.** An AI-powered weather monitoring system that visualizes real-time cloudburst risk across India on an interactive map, backed by machine learning models trained on historical weather patterns and satellite data.

**Architecture & engineering notes**
- **Geospatial layer** — Leaflet.js renders per-region risk across India, updating against live inputs rather than static snapshots.
- **Data source** — NASA IMERG precipitation API, providing satellite-derived rainfall measurement as the ground truth for the risk model.
- **ML layer** — predictive risk assessment over historical rainfall patterns, producing probability rather than a binary alarm.
- **Analytics** — Chart.js dashboards for rainfall analytics and risk probability trends over time.
- **Security** — this was the part I spent the most time on. Input sanitization and XSS prevention across all user-supplied fields, plus **GPS spoofing detection**, since a location-based warning system that trusts client-reported coordinates is a system that can be fed false coordinates on purpose.

**Why it's hard.** Geospatial ML is mostly a data-integrity problem. A risk map is only as trustworthy as its least-validated input, which is why the threat model came before the model.

### 🖥️ Hypervisor-Based Sandbox with Live Resource Monitoring

> **Problem.** Analysing untrusted code means running it somewhere it can't reach anything that matters — and watching what it does while it runs.

**What it does.** A sandbox management platform for provisioning, controlling, and observing virtual machines in real time.

**Architecture & engineering notes**
- **Isolation model** — hypervisor-level separation, so untrusted workloads are contained at the VM boundary rather than the process boundary.
- **Control plane** — Flask backend exposing full VM lifecycle operations: start, stop, and reset.
- **Telemetry** — live CPU, memory, and disk utilisation tracking, streamed into dynamic visualisation charts so resource behaviour is visible as it happens, not after the fact.
- **Interfaces** — a responsive React dashboard for browser-based management, plus a Tkinter desktop client; SQLite for VM state and session persistence.

**Why it's hard.** Real-time telemetry and lifecycle control fight each other — polling frequently enough to be useful without the monitoring itself distorting the resource numbers you're trying to measure.

### 📊 Instagram Analyser

> **Problem.** Influencer marketing decisions get made on follower counts, which are the single least informative number on the profile.

**What it does.** A web tool that analyses Instagram influencer profiles and engagement metrics, modelling the account's network rather than just counting it.

**Architecture & engineering notes**
- **Graph modelling** — influencer connections and engagement patterns represented as a graph, with traversal algorithms surfacing relationship structure that flat metrics miss.
- **Backend** — Flask service layer with SQLite for efficient storage and retrieval of profile data and computed analytics.
- **Frontend** — HTML/CSS/JavaScript dashboard for metric exploration.
- **Security** — built with attention to safe handling of scraped and user-submitted data.

**Why it's hard.** Engagement authenticity is a graph property, not a scalar. Getting there meant treating the follower network as the actual dataset.
